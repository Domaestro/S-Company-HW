Набор простых функций на C, которые после компиляции под **RV32I** в получившемся ассемблерном листинге дают инструкцию каждого основного формата:

- **R-type**
- **I-type**
- **S-type**
- **B-type**
- **U-type**
- **J-type**

Далее идет сравнение результата компиляции:

- без оптимизаций (`-O0`) — чтобы хорошо увидеть, как исходный код отображается в ассемблер;
- с оптимизациями (`-O2`) — чтобы  сравнить, как компилятор сокращает код и заменяет одни конструкции другими.

Команды компиляции компиляции:

```bash
clang -target riscv32 -march=rv32i -mabi=ilp32 -S -O0 rv32i_demo.c -o rv32i_demo_O0.s
clang -target riscv32 -march=rv32i -mabi=ilp32 -S -O2 rv32i_demo.c -o rv32i_demo_O2.s
```

Во всех функциях используется:

```c
__attribute__((noinline))
```

Он запрещает компилятору **встраивать функцию в место вызова** (*inline expansion*).

Это важно здесь по двум причинам:

1. **Функция гарантированно остается отдельной функцией в ассемблере.**  
   Если компилятор встроит ее в другое место программы, то отдельный листинг функции может исчезнуть.

2. **Проще анализировать, какая именно конструкция на C породила нужную инструкцию RV32I.**  
   Без `noinline` часть маленьких функций на `-O2` могла бы полностью исчезнуть как самостоятельные единицы.

## 1. Функция `add_r`

### Листинг на C

```c
__attribute__((noinline))
int add_r(int a, int b) {
    return a + b;
}
```

### Результат компиляции `-O0`

```asm
add_r:
	addi	sp, sp, -16
	sw	ra, 12(sp)
	sw	s0, 8(sp)
	addi	s0, sp, 16
	sw	a0, -12(s0)
	sw	a1, -16(s0)
	lw	a0, -12(s0)
	lw	a1, -16(s0)
	add	a0, a0, a1
	lw	ra, 12(sp)
	lw	s0, 8(sp)
	addi	sp, sp, 16
	ret
```

### Результат компиляции `-O2`

```asm
add_r:
	add	a0, a1, a0
	ret
```

### Разбор

Эта функция предназначена для получения инструкции **R-type**.

Главная инструкция здесь:

```asm
add a0, a0, a1
```

или в оптимизированной версии:

```asm
add a0, a1, a0
```

Порядок операндов может немного отличаться, но смысл одинаковый: сложение двух регистров с записью результата в регистр назначения.

**R-type**:

- оба исходных операнда находятся в регистрах (`rs1`, `rs2`);
- результат записывается в регистр (`rd`);
- immediate в этой инструкции нет.

## 2. Функция `load_i`

### Листинг на C

```c
__attribute__((noinline))
int load_i(int* p) {
    return p[3];
}
```

### Результат компиляции `-O0`

```asm
load_i:
	addi	sp, sp, -16
	sw	ra, 12(sp)
	sw	s0, 8(sp)
	addi	s0, sp, 16
	sw	a0, -12(s0)
	lw	a0, -12(s0)
	lw	a0, 12(a0)
	lw	ra, 12(sp)
	lw	s0, 8(sp)
	addi	sp, sp, 16
	ret
```

### Результат компиляции `-O2`

```asm
load_i:
	lw	a0, 12(a0)
	ret
```

### Разбор

Эта функция нужна для демонстрации **I-type** на примере загрузки из памяти.

Ключевая инструкция:

```asm
lw a0, 12(a0)
```

Она загружает слово по адресу `a0 + 12`. Так как `p` — это указатель на `int`, выражение `p[3]` означает чтение элемента со смещением `3 * 4 = 12` байт.

 **I-type**:

- используется один базовый регистр (`rs1`);
- есть 12-битное смещение `imm`;
- результат записывается в `rd`.

## 3. Функция `store_s`

### Листинг на C

```c
__attribute__((noinline))
void store_s(int* p, int x) {
    p[2] = x;
}
```

### Результат компиляции `-O0`

```asm
store_s:
	addi	sp, sp, -16
	sw	ra, 12(sp)
	sw	s0, 8(sp)
	addi	s0, sp, 16
	sw	a0, -12(s0)
	sw	a1, -16(s0)
	lw	a0, -16(s0)
	lw	a1, -12(s0)
	sw	a0, 8(a1)
	lw	ra, 12(sp)
	lw	s0, 8(sp)
	addi	sp, sp, 16
	ret
```

### Результат компиляции `-O2`

```asm
store_s:
	sw	a1, 8(a0)
	ret
```

### Разбор

Эта функция демонстрирует **S-type**.

Ключевая инструкция:

```asm
sw a1, 8(a0)
```

Смысл инструкции:

- `a0` содержит адрес массива `p`;
- `a1` содержит значение `x`;
- смещение `8` соответствует элементу `p[2]`, потому что `2 * 4 = 8` байт.

**S-type**:

- выполняется запись в память;
- один регистр задает базовый адрес (`rs1`);
- второй содержит записываемые данные (`rs2`);
- смещение хранится в поле immediate формата S.

## 4. Функция `branch_b`

### Листинг на C

```c
__attribute__((noinline))
int branch_b(int a, int b) {
    if (a == b)
        return 1;
    else
        return 0;
}
```

### Результат компиляции `-O0`

```asm
branch_b:
	addi	sp, sp, -32
	sw	ra, 28(sp)
	sw	s0, 24(sp)
	addi	s0, sp, 32
	sw	a0, -16(s0)
	sw	a1, -20(s0)
	lw	a0, -16(s0)
	lw	a1, -20(s0)
	bne	a0, a1, .LBB3_2
	j	.LBB3_1
.LBB3_1:
	li	a0, 1
	sw	a0, -12(s0)
	j	.LBB3_3
.LBB3_2:
	li	a0, 0
	sw	a0, -12(s0)
	j	.LBB3_3
.LBB3_3:
	lw	a0, -12(s0)
	lw	ra, 28(sp)
	lw	s0, 24(sp)
	addi	sp, sp, 32
	ret
```

### Результат компиляции `-O2`

```asm
branch_b:
	xor	a0, a0, a1
	seqz	a0, a0
	ret
```

### Разбор

Эта функция была написана для получения инструкции **B-type**.

В версии `-O0` главная инструкция:

```asm
bne a0, a1, .LBB3_2
```

**B-type**:

- инструкция выполняет условный переход;
- сравниваются два регистра;
- адрес перехода задается смещением специального branch-формата.

Также в листинге видны инструкции:

```asm
j .LBB3_1
j .LBB3_3
```

Здесь `j` — это псевдоинструкция для `jal x0, label`, использование формата **J-type**.

Самое интересное происходит на `-O2`: компилятор полностью убирает ветвление и заменяет его на арифметику без переходов:

```asm
xor  a0, a0, a1
seqz a0, a0
```

Логика такая:

- `xor` дает ноль, если `a == b`;
- `seqz` возвращает `1`, если результат равен нулю.

То есть после оптимизации функция больше не содержит явной branch-инструкции.

## 5. Функция `make_u`

### Листинг на C

```c
__attribute__((noinline))
int make_u(void) {
    return 0x12345000;
}
```

### Результат компиляции `-O0`

```asm
make_u:
	addi	sp, sp, -16
	sw	ra, 12(sp)
	sw	s0, 8(sp)
	addi	s0, sp, 16
	lui	a0, 74565
	lw	ra, 12(sp)
	lw	s0, 8(sp)
	addi	sp, sp, 16
	ret
```

### Результат компиляции `-O2`

```asm
make_u:
	lui	a0, 74565
	ret
```

### Разбор

Эта функция демонстрирует **U-type**.

Ключевая инструкция:

```asm
lui a0, 74565
```

Инструкция `lui` загружает старшие 20 бит константы в регистр, то есть формирует значение вида:

```text
imm << 12
```

Для данной функции это как раз соответствует константе `0x12345000`.

**U-type**:

- у инструкции есть большое поле immediate, занимающее старшие 20 бит;
- нижние 12 бит после `lui` равны нулю;
- инструкция предназначена именно для построения больших констант.

## 6. Функция `jump_j`

### Листинг на C

```c
__attribute__((noinline))
int jump_j(int x) {
    if (x < 0)
        x = -x;
    return x;
}
```

### Результат компиляции `-O0`

```asm
jump_j:
	addi	sp, sp, -16
	sw	ra, 12(sp)
	sw	s0, 8(sp)
	addi	s0, sp, 16
	sw	a0, -12(s0)
	lw	a0, -12(s0)
	bgez	a0, .LBB5_2
	j	.LBB5_1
.LBB5_1:
	lw	a1, -12(s0)
	li	a0, 0
	sub	a0, a0, a1
	sw	a0, -12(s0)
	j	.LBB5_2
.LBB5_2:
	lw	a0, -12(s0)
	lw	ra, 12(sp)
	lw	s0, 8(sp)
	addi	sp, sp, 16
	ret
```

### Результат компиляции `-O2`

```asm
jump_j:
	srai	a1, a0, 31
	xor	a0, a0, a1
	sub	a0, a0, a1
	ret
```

### Разбор

В версии `-O0` в листинге есть строки:

```asm
j .LBB5_1
j .LBB5_2
```
`j` — это псевдоинструкция. Для RV32I она разворачивается в:

```asm
jal x0, label
```

**J-type**.

в начале функции присутствует:

```asm
bgez a0, .LBB5_2
```

Это уже условный переход branch-класса.

На `-O2` компилятор убирает переходы:

```asm
srai a1, a0, 31
xor  a0, a0, a1
sub  a0, a0, a1
```
